# 2026 VPN推荐：先看懂封锁怎么运作，再决定买什么

> 中国大陆直连环境实测 · 协议原理与选型方法 · 2026 年 11 月

大多数人挑 VPN 的路径是：搜"哪个 VPN 好"，看一张参数表，挑节点最多、评分最高的那个。

这条路对中国大陆用户是反的。原因很简单：**你打开那些官网本身就需要先翻墙，而你要买的正是那个能让你翻墙的东西。**

这不是段子。下面第一节那张表里，六行是 15 秒超时。

本文分两半。前半部分讲中国大陆的网络为什么"打不开"、主流翻墙协议各自在躲什么。这部分和买谁无关——看懂之后，参数表你自己就能读。后半部分才是选型标准、实测数据和排查方法。

## 二、跨境访问卡在哪：三道关卡

从你的设备到一个境外网站，中间至少有三道可以下手的关卡。任何一道拦住你，页面就是打不开。

![三道关卡示意]({{ '/assets/img/blocking.svg' | relative_url }})

*图 2：DNS 解析、IP 连接、协议特征——三道关卡拦住三种不同层面的访问。*

第一道在"名字翻译成地址"这一步，第二道在"地址能不能连上"，第三道在"连上了，但流量长什么样"。三道关卡的原理不一样，绕过它们需要的东西也不一样。把三道混为一谈，是很多"攻略"讲不清楚的根源。

## 三、第一关：DNS 污染

你在浏览器里输入域名，系统先要问一句：这个域名对应哪个 IP。这个"问"就是 DNS 查询。

问题的关键在于，传统 DNS 走的是**明文的 UDP 53 端口**。链路上任何一台设备都能看到你在问什么，也能抢在真正的服务器之前回答你。这就是 DNS 污染：你收到一个伪造的地址，连过去要么是空的，要么是别人的服务器。

三个常被误解的点：

**第一，污染发生在查询阶段，不是访问阶段。** 所以"换个浏览器""清一下缓存"没有用，问题不在你本机。

**第二，改用 DoH / DoT 能解决"被伪造回答"，但不解决"连不上"。** DNS over HTTPS 和 DNS over TLS 把查询本身加密了，伪造的回答插不进来。可如果目标 IP 本身就在封锁名单上，你查到了正确答案，一样连不上。这两件事必须分开看。

**第三，DNS 污染可以被用来做定向投放。** 伪造的回答不一定是个死地址，也可能是某个能正常打开的页面。所以"能打开"不等于"打开的是真的"。

## 四、第二关：IP 封锁与 TCP 重置

拿到 IP 之后，你的设备会发起 TCP 握手。这一步拦起来最直接：**在路由层把目标 IP 丢掉**，你的连接请求就永远等不到回应，表现就是超时。

IP 封锁有两个特征值得知道：

**它是按 IP 段批量执行的，不是按域名。** 同一个 IP 上挂着的其他站点会一起受影响。这也是为什么有些自建方案换个域名没用，得换 IP。

**它经常是临时的、有选择的。** 热门目标可能长期封，冷门目标可能只是风头紧时被封几天。你昨天能连、今天不能，不代表服务坏了。

比丢弃更"精细"的手段是 TCP RST 注入：连接已经建立，中间设备识别出你不该连这里，就分别向两端发送伪造的 RST 包，把连接掐断。你会看到"连接被重置"而不是"超时"——**这两个错误信息本身就提示了拦截发生在哪一层**。

## 五、第三关：深度包检测与协议指纹

第三道关卡最麻烦：连接已经建立，数据在正常传输，中间设备开始检查**流量长什么样**。

传统防火墙只看 IP 和端口。深度包检测（DPI）会往应用层看：TLS 握手里的 SNI 写了哪个域名、证书是谁签的、包的长度和间隔有没有规律、是不是"一条 TLS 隧道里又套了一条 TLS 隧道"。

![DPI 看到的两种流量]({{ '/assets/img/dpi.svg' | relative_url }})

*图 3：自定义协议有固定头部，容易被认出；伪装成常规 HTTPS 的流量与真实网站同类，难以区分。*

这就解释了一个最常见的困惑：**为什么"加密了"还是会被封？**

因为加密保护的是内容，不保护形式。你用 256 位 AES 加密一条隧道，DPI 看不到里面传了什么，但它能看出"这里有一条隧道"。一条长期存在、包长规律、只连一个境外 IP 的加密连接，本身就是特征。

围绕这一点，过去十年的技术演进基本就一条主线：**让流量越来越像"正常的网页访问"。** 下一节按这条线把主流协议排一遍。

## 六、协议谱系：从明文隧道到"借用真网站"

下面这张表按"像不像正常流量"从弱到强排列。抗封锁一列的判断依据是伪装强度，不是速度，也不是"官方宣称"。

| 协议 | 传输层 | 伪装方式 | 抗封锁 | 说明 |
|---|---|---|---|---|
| Shadowsocks | TCP | 无 TLS，字节流看似随机 | 低—中 | 老牌方案，无握手特征但也无伪装，可被长度与时序分析识别 |
| SSR | TCP | 在 SS 上加混淆参数 | 低—中 | 混淆参数一旦被提取，整套失效 |
| VMess（V2Ray） | TCP / WS / gRPC | 自定义头部 + 传输层伪装 | 中 | 需要客户端与服务端版本匹配，头部可被针对性分析 |
| VLESS | 同上 | 自带不加密，依赖传输层 | 中—高 | 配合 TLS/Reality 时才强；单独使用时很轻但很裸 |
| Trojan | TCP | **真 TLS**，证书合法 | 高 | 对外就是一个 HTTPS 网站，探测访问会看到正常页面 |
| Hysteria2 / TUIC | QUIC（UDP） | 真 TLS over QUIC | 中—高 | 高丢包、高延迟链路下表现明显更好 |
| Reality | TCP（TLS 1.3） | **借用真实站点的证书与握手** | 高 | 不需要自有域名和证书，主动探测会看到那个真实网站 |
| WireGuard | UDP | 固定长度握手包 | 低 | 速度快、实现简洁，但握手格式固定，易被指纹识别 |
| OpenVPN | TCP / UDP | 自有握手 | 低—中 | 兼容性最好；TCP 模式的特征更明显 |
| NaiveProxy | HTTP/2、HTTP/3 | 完整 Chromium 网络栈 | 高 | 特征最接近真实浏览器，部署门槛也最高 |

几个值得单独说清楚的：

**Shadowsocks 不是"不可检测"。** 它的设计目标是让流量看起来随机，而不是看起来像 HTTPS。随机流量在统计上反而可疑：正常网页访问有清晰的 TLS 握手、有明显的请求响应节奏，一条从头到尾均匀加密、只连单一出口的长连接，本身就是异常。它当年能流行，是因为对手还很粗糙；现在不是了。

**Trojan 和 Reality 的思路不一样，效果相近。** Trojan 需要你自己有一个域名和一张合法证书，然后把这个网站真的搭起来，代理只是在 TLS 之后跑。Reality 更省事也更难缠：它直接借用某个真实网站的证书完成握手，没有正确凭据的探测请求会被转发给那个真实网站，所以主动探测看到的是一个正常网站，而不是一个"可疑的空服务"。

**WireGuard 快，但它是为"可信网络"设计的。** 它的握手包长度固定、结构清晰，这在企业内网里是优点，在审查环境里是明码标价。商业 VPN 普遍主打 WireGuard 系协议，买之前要想清楚：速度快和连得上，在高封锁环境下经常是两件事。

**QUIC 类协议（Hysteria2、TUIC）解决的是另一个问题。** 它们对丢包和延迟的容忍度更高，在跨境这种高抖动链路下，体感速度可能比 TCP 系协议好很多。代价是 UDP 流量在某些网络里会被限速甚至直接丢弃。

## 七、加密解决什么，不解决什么

这一节值得单独写，因为"军用级加密""银行级加密"这类说法几乎出现在每一份 VPN 广告里，而它和你能否连上，没有直接关系。

加密解决三件事：

- **机密性**——中间人看不到内容
- **完整性**——内容被篡改能被发现
- **身份验证**——你连的是真的服务端

加密不解决三件事：

- **你连不连得上**：目标 IP 被丢，握手就完不成，加密强度再高也没用
- **别人知不知道你在用代理**：包长、时序、连接目标、SNI，这些都在密文外面
- **服务端可不可信**：端到端加密的前提是两端你都信。你把流量交给一个 VPN 服务商，它就处在能看到你全部明文的位置

所以看到"256 位 AES""军用级"这类词，正确的理解是：**它说明内容保护达标，仅此而已。** 这句话在 2026 年对绝大多数产品都成立，不构成任何差异化。

真正决定你能不能用的，是前面三道关卡怎么过，以及——下面这两节——出口在物理上怎么走。

## 八、公网、中转与专线：钱花在哪一层

同样是"一个境外出口"，物理路径可以差很多，抗封锁能力和价格也差很多。

![三条出境路径]({{ '/assets/img/path.svg' | relative_url }})

*图 4：公网直连三关全暴露；普通隧道底层仍走公网；IEPL/IPLC 专线不经过公网审查设备。*

**公网直连。** 数据走公共互联网出境，经过国际网关。三道关卡全暴露，最便宜，也最容易被拦。

**普通 VPN / 代理隧道。** 内容加密了，但底层仍然是公网。第三关（协议指纹）依然在，能不能过取决于协议伪装得够不够像正常流量。

**中转。** 先连到离你较近的境内或近境入口，再由入口转发出去。它能改善第一段的质量（降低丢包、稳定延迟），但第一段仍然是公网，仍然可能被拦。中转解决的是"快不快、稳不稳"，不是"通不通"。

**IEPL / IPLC 专线。** 走运营商提供的私有国际专线，不经过公共互联网的国际网关，因此常规的公网 DPI 不在这条路径上。代价是成本高出一个量级，通常只有付费套餐才会用；而且专线供应商本身受监管，通道被关停时用户没有办法。

**这个区分很重要：** 很多服务宣传"专线加速"，实际是"中转"；"中转"和"专线"的价格差好几倍，效果也不同。买之前值得问一句：这一段到底是公网还是私有电路。

**厂商说"专线"，你怎么核实？** 没有一个公开工具能证明某一段是私有电路，但有几个间接办法：

- **看价格。** 真正的 IEPL/IPLC 按带宽计费，成本以千元每月为单位。月费 ¥30 还宣称"全线路专线"的产品，要么专线只覆盖部分入口、要么是"专线入口 + 公网出口"的混合结构。
- **看延迟稳定性。** 专线的特点是抖动小，不是延迟低。同一节点连续测 20 次，专线类链路的标准差通常远小于公网中转。
- **看高峰时段。** 公网线路晚高峰（20:00–23:00）会明显掉速，专线受影响小得多。这是最容易自己验证的一项。
- **看它敢不敢写清楚。** 敢在官网写明"哪条线路是专线、覆盖哪些入口、峰值带宽多少"的，通常比只写"专线级网络"的可信。

## 九、VPN、机场、客户端：三个常被混用的词

中文语境里这三个词经常混着用，但它们指的不是一回事。

**VPN**——严格意义上的虚拟专用网。一条加密隧道，从你的设备连到一个出口，所有流量走这一条。商业 VPN 就是这种形态：一个客户端，一个"连接"按钮，选一个国家。

**机场**——用户对"提供多个代理节点订阅的服务"的俗称。它通常不是单一隧道，而是给你一串节点，按流量或时长计费。节点可能跑 SS、VMess、Trojan、Hysteria2 等不同协议。

**客户端**——只是工具。Clash 系列、v2rayN、Shadowrocket、NekoBox 这些，自己不具备任何"翻墙能力"，它们只是把配置里的节点连起来。客户端是免费的，收费的是节点。

三者的关系是：**机场提供节点，客户端连接节点，VPN 通常是"机场 + 客户端 + 出口"打包成一个省事的产品。** 商业 VPN 卖的是"不用自己配"，机场卖的是"节点便宜、选择多"。

理解了这一层，很多宣传话术就不难拆穿："自研协议"多半是某个开源协议的改名，"军用级加密"是标配，"全球节点"要问的是其中几个标称中国大陆可用。

**术语速查**

| 词 | 实际含义 | 常见误用 |
|---|---|---|
| 节点 | 一台可连接的境外服务器 | 被当成"服务"，其实只是出口 |
| 线路 / 航线 | 到达某个节点的具体网络路径 | 与节点混为一谈，但同一节点可有多条线路 |
| 中转 | 先连入口、再由入口转发出去 | 被宣传成"专线" |
| 落地 | 最终访问目标网站的那个出口 | 被宣传成"节点" |
| 解锁 | 出口 IP 未被目标平台封禁 | 被宣传成"永久有效" |
| 订阅 | 一串节点的配置文件链接 | 被当成"客户端"，其实只是配置 |
| 分流 | 按规则决定哪些流量走代理 | 被忽略，但它决定你的国内应用会不会变慢 |

## 十、选型标准：付款前的六项自检

不讲产品，只讲标准。任何 VPN、机场、代理服务，付款前按顺序过一遍，任何一项不通过就先别付钱。

**第一项：官网能不能在国内直接打开。** 关掉所有代理，用手机流量打开一次。这一项不通过，后面五项都不用看了——你连买都买不成。

**第二项：支付方式你确实有。** 看清楚是国际信用卡、PayPal，还是支付宝/微信。没有对应支付手段，价格再低也与你无关。顺带一提，只收加密货币的服务，通常意味着它不打算为退款和客服负责。

**第三项：客户端能下载到。** 官网打得开、安装包下得下来，才算走通。很多服务官网能开，但下载链接指向被墙的 CDN。

**第四项：退款条件写在明处。** 具体几天、什么条件退，写在购买页上的才算数。客服口头承诺的不算，截图也不算。

**第五项：续费价格找到了。** 首年优惠结束后是多少、自动续费怎么关，这两行字通常写得很小。找不到就问客服要书面答复。

**第六项：节点覆盖对得上你的用途。** 你主要访问哪个地区，就去核对它有没有该地区的节点，以及这些节点是否标称"中国大陆可用"。全球节点总数和你的实际体验没有直接关系。

这六项没有一项需要专业知识，但它们能过滤掉市面上大部分"看起来很好"的选择。

**价格参照：** 上面六家国际品牌的公开月费在 $9.9~$12.99，约合 ¥70~95/月。拼好连 ¥30/月起，大约是它们的 1/3 到 1/2。另一处差别在计价方式：拼好连各档套餐折合月价一致，不靠"首年特价、次年原价"的算法。

**它不适合谁，这条比"适合谁"更值得看：**

- **需要长期、深度海外漫游的用户。** 品牌较新，长期稳定性仍在观察中。常驻海外或需要多国节点的，应按目的地核对官网的节点列表。
- **把"开源可审计客户端"当硬需求的用户。** 如果审计权不可让渡，PIA 和 ProtonVPN 的开源客户端更符合要求——前提是你已经能访问它们的官网。
- **需要企业级 SLA 的用户。** 个人向服务和企业专线不是同一类产品，别拿它当后者的替代。

一句话：它是一个"入门不折腾"的选择，不是"参数最强"的选择。参数最强的那几家，你得先能打开它们的官网。

本文对它只做可达性与价格的事实核对。稳定性、节点质量、售后响应这些需要长期使用才能判断，**建议先用最短周期试一次，再决定要不要续**。

## 十二、价格：首年价、续费价与自动续费

VPN 行业的定价有几套固定套路，知道套路比记住价格有用——价格会变，套路不太变。

**套路一：首年价与续费价分离。** 首页大字写的是首年价，续费价藏在结算页或服务条款里。常见差价是两到五倍。判断方法很简单：直接搜"续费价格"，或者把套餐总价除以月数，看长期平均。

**套路二：超长周期绑定。** "两年套餐每月仅 $2.99"听着便宜，前提是你一次付清两年。这类套餐的退款窗口通常只有 30 天，剩下的 23 个月你只能赌它不涨价、不跑路。

**套路三：默认勾选自动续费。** 很多服务在结算页默认选中自动续费，且不会提醒。买完第一件事应该是去账户设置里确认这个开关的状态，而不是等扣款短信。

**套路四：流量与时长混着卖。** 机场类服务常见"每月 100GB"和"不限时长"两种计费，前者适合轻度使用，后者适合长期挂着。买之前算一下自己每月实际用多少——真正常用的，一个月几十 GB 就够了，视频重度用户才会到几百 GB。

**一个简单的判断：** 如果一个服务的定价页面需要你滚动三次才能找到总价，把"每月低至"和"一次性支付"分开写在不同位置，这本身就是一种信号。

**顺手一提：VPN 与代理只保护走它的流量。** 开着"全局代理"能让所有流量都走，但同时你的国内应用也会绕一圈境外，速度变慢、部分服务还会因为异地登录被风控。这就是下面这一节的问题。

## 十三、分流：决定你日常体验的那条规则

同一份节点，不同的分流规则，体验可以差很多。这是最影响长期使用感受、却最少被讲清楚的一环。

**大局域网模式（全局代理）。** 所有流量都走代理。好处是省心，坏处是所有国内应用也走境外：视频加载慢、网银可能触发风控、外卖和地图定位漂移。指不定哪天你的账号被判定为"异地登录"。

**规则模式（分流）。** 按规则判断：国内域名和 IP 走直连，境外走代理，剩下不确定的按预设策略处理。这是绝大多数人应该用的模式。代价是需要一份维护得不错的规则集，规则过期会出现"该走的没走、不该走的绕了"。

**白名单模式。** 只有你明确列出的流量走代理，其余全部直连。最省流量、最不影响国内应用，但需要自己维护名单，漏了就上不去。

选择建议很直接：**不确定就先用规则模式**，观察一周。如果发现某个国内应用明显变慢，把它加进直连名单；如果发现某个境外站点上不去，把它加进代理名单。这套微调比换节点更能改善日常体验。

还有一个常被忽略的细节：**分流对 DNS 的要求。** 国内域名必须用国内 DNS 解析，境外域名必须用加密 DNS 解析，否则会出现"域名解析到境外 CDN 节点、但走的是直连"，结果慢到不可用。这是很多"感觉 VPN 很慢"问题的真正原因。

## 十四、免费方案的真实成本

免费 VPN 有三类限制，先看你能否接受：

- **限速**——能一直用，速度压在很低的水位
- **限量**——每月几百 MB 到几 GB，正常使用几天就没了
- **限节点**——只开放少数几个国家和地区

比限制更该注意的是商业模式。服务器、带宽、IP 都是真金白银，免费服务的钱从哪来？常见答案有几个：

**卖数据。** 你的访问记录、设备信息、位置数据，对广告商和数据分析公司有价值。隐私政策里写"我们可能与合作伙伴共享匿名化数据"的，值得多看两眼——"匿名化"的定义通常很宽。

**插广告。** 客户端里塞广告位，甚至劫持你访问的页面注入广告。这类行为在移动端免费 VPN 里尤其常见。

**拿你的设备当出口。** 少数免费服务会把你加入 P2P 出口池，让别人的流量从你的网络出去。这在服务条款里往往写得很含糊。

**随时停服。** 免费服务的存续完全取决于运营方的意愿，没有任何承诺。把它当临时应急可以，当长期方案不合适。

对"只是想偶尔看看"的人，免费方案确实够用；对每天都要用的人，花 ¥30 买稳定，比在免费方案里反复折腾便宜。

## 十五、自建服务器：什么时候值得，什么时候不值得

自建（买一台境外 VPS，自己装协议服务端）在技术圈很流行，但它不是万能答案。

**适合自建的情况：**

- 你已经有境外服务器，且这台机器本来就用于别的用途
- 你有能力处理证书、域名、服务端更新
- 你的使用强度低，且能接受"IP 被封就换一台"的成本
- 你对"节点不经过第三方服务商"有明确需求

**不适合自建的情况：**

- **你连 VPS 都买不到。** 大多数境外 VPS 商同样只收国际信用卡，同样面对官网可达性问题。这一步没走通，自建方案一开始就不成立。
- **你只有一台 IP。** 单 IP 是最脆弱的形态，被封之后要么换 IP（很多商家收费），要么整台重买。
- **你没有维护时间。** 协议服务端有安全更新，证书会过期，机器会被扫描。长期不维护的自建节点，安全性可能不如成熟商业服务。
- **你需要的不是"一个节点"，而是"稳定的出口"。** 商业服务的价值在于有备用节点、有人值班、出了问题有客服。

一个常见的误区是"自建一定更安全"。实际上，自建的安全性完全取决于你的运维水平；而商业服务的隐私性取决于它的日志政策。两者都不是天然更好，要看具体实现。

## 十六、按用途选：同一种需求，不同的重点

VPN 不是单一品类。用途不同，该看的指标完全不同。

**看流媒体（Netflix、Disney+、YouTube 等）**

关键不是带宽，是**IP 类型**。流媒体平台会判断出口 IP 属于数据中心还是住宅网络，以及 IP 的地理位置数据库记录。同一个服务，不同节点解锁情况可能完全不同。要看的是"哪个节点能解锁"，而不是"节点总数"。

**玩游戏**

关键不是带宽，是**延迟和丢包**。跨境游戏的瓶颈几乎总是在物理距离和链路抖动上。UDP 转发能力、是否有游戏专线、节点到你常用服务器区的延迟，这三点比"千兆带宽"重要得多。另外，部分游戏会检测 VPN 并封号，用之前先确认游戏条款。

**下载与大文件传输**

这里是带宽真正起作用的地方。但要注意流量配额：很多套餐写着"不限流量"，实际有公平使用条款，持续满载会被限速。

**远程办公 / 访问公司内网**

这类需求通常不该用商业 VPN 解决，应该用公司提供的企业 VPN 或零信任接入。拿个人翻墙工具连公司内网，在多数公司的安全规范里是不允许的。

**AI 服务（ChatGPT、Claude、Gemini 等）**

这类服务的地区限制比流媒体更严格，且对数据中心 IP 的识别更积极。需要的是目标地区的稳定出口，且要接受"随时可能被调整"的现实。同时注意：账号所在地区与出口 IP 地区不一致，本身可能违反服务条款。

## 十七、连不上时怎么排查

出现问题时，先定位在哪一层。下面六步按"从便宜到贵"排序，多数问题在前三步就能定位。

**第一步：确认是不是 DNS 的问题。** 用 IP 直接访问目标（如果知道 IP），或者换一个加密 DNS（DoH）再试。能通说明是解析被污染，不是 IP 被封。

**第二步：看错误信息的类型。** "超时"多半是 IP 层被丢包；"连接被重置"多半是握手阶段被识别；"证书错误"可能是被中间人劫持。这三种指向完全不同的原因。

**第三步：换协议而不是换节点。** 如果同一个服务有多个协议，先换协议。协议被针对的可能性远高于节点故障。

**第四步：换网络环境。** 手机热点、不同运营商、不同时段各试一次。有些封锁是分运营商、分时段执行的。

**第五步：检查本机。** 系统时间偏差过大会导致 TLS 握手失败；代理软件的规则可能把目标流量走了直连；本地防火墙可能拦了 UDP。

**第六步：确认服务端还活着。** 换一个你确定能用的旧节点做对照。如果旧节点也全挂，问题在客户端或账号，不在线路。

**一个容易被忽略的点：** 换了节点就好、过一会儿又不行，通常是那个 IP 正在被封的过程中，不是你的配置错了。这种情况下反复重连没有意义，换节点更快。

## 十八、常见问题

**官网打不开，但产品听说很好用，能买吗？**

不能直接买。你必须先有另一个可用的翻墙方式，才能打开官网、完成支付、下载客户端。如果你已经有一个能用的工具，可以把它当备选；如果没有，这条路走不通。

**为什么国际大牌都不支持支付宝？**

不是不支持，是面向的市场不同。NordVPN、ProtonVPN 这类产品的默认客群在欧美，支付体系按当地习惯搭建。中国大陆用户不是它们的主要市场，所以既没有本地支付渠道，也没有针对高封锁环境的官方支持承诺。

**便宜的会不会不稳定？**

价格和稳定性没有必然关系，但**品牌年龄**和稳定性有关系。新品牌需要用时间验证，这是客观事实，不该被宣传掩盖。合理的做法是先用最短周期试，而不是一次买两年。

**协议越新越好吗？**

不一定。新协议通常针对最新的检测手段设计，但部署复杂度更高、客户端支持更少、出问题时更难排查。Reality 比 SS 强，前提是你能正确部署它。部署错的 Reality，安全性不如部署对的 Trojan。

**"不限流量"是真的不限吗？**

看条款。多数"不限流量"附带公平使用条款，持续高占用会被限速或要求升级。真正不限的通常是专线类产品，价格另说。

**用 VPN 看视频会不会被平台封号？**

有可能。流媒体平台的服务条款通常限制跨区访问，部分平台会检测代理并对账号采取措施。风险大小因平台而异，本文不给规避建议。

**手机和电脑能同时用吗？**

看套餐的设备数限制。多数商业服务允许 3~10 台设备，机场类通常按连接数或 IP 数限制。买之前确认这个数字，多设备用户容易忽略。

**节点越多越好吗？**

不是。一个能稳定连上的节点，价值大过十个连不上的。看节点数时同时问一句：这些节点里，有几个标称中国大陆可用？

**续费涨价了怎么办？**

先看当初的条款有没有承诺续费价。没有承诺的，涨价是正常商业行为。做法是到期前一个月核对价格，不接受就换，不要等自动扣款。

**这页的数据多久更新一次？**

可达性和价格每月复核一次。网络环境会变，任何人的官网可达性都可能改变——包括本页提到的服务。付款前请自己去官网确认当前状态。

## 十九、实测方法与数据：你可以自己复现

不要只信本文。第一节那张表任何人都能复现：

```bash
# 在中国大陆网络环境下，关掉代理，直接访问
curl -o /dev/null -w "%{http_code} %{time_total}\n" --max-time 15 https://pinghaolian.live/
curl -o /dev/null -w "%{http_code} %{time_total}\n" --max-time 15 https://nordvpn.com/
```

返回 `301 2.0`（或 `200`）表示可达；返回 `000 15.0` 表示 15 秒超时、不可达。

**本次实测的完整延迟分布**（12 次采样，`curl -L` 跟随跳转至最终 200）：

| 指标 | 值 |
|---|---|
| 最小值 | 1.70 s |
| 中位数 | 2.24 s |
| p90 | 4.28 s |
| 最大值 | 4.45 s |

只测第一跳 301 时，中位数约 1.4 秒。跳转链是 `pinghaolian.live`（Cloudflare，返回 301）→ `www.pinghaolian.live`（国内节点，返回 200），所以总耗时里包含一次跨域名跳转。**只看 301 会低估实际打开时间，只看单次结果会得出错误结论**——这也是本文用分布而不是单点数字的原因。

作为对照，六个境外官网在同样条件下全部返回 `000 15.0`：15 秒内没有任何响应，TCP 握手都没完成。

几个让结果更可信的细节：

- **一定要关代理。** 开着代理测出来的是"你的代理能不能连官网"，不是"国内能不能直连"。
- **重复三次。** 单次超时可能是瞬时抖动，三次全超时才有说服力。
- **记录出口 IP 归属地。** 用手机流量和宽带分别测一次，不同运营商的结果可能不同。
- **记录日期。** 可达性是有保质期的数据，没有日期的结论没有意义。

**本文实测日期：2026 年 11 月 11 日，中国大陆直连环境。** 这个结论会过期。付款前请自己再确认一遍。

## 二十、合规与风险提示

这一节不是套话，是选型时必须知道的前提。

在中国大陆，国际联网需要使用国家批准的信道。《计算机信息网络国际联网管理暂行规定》对未经批准擅自使用其他信道进行国际联网的行为规定了处理措施。个人使用未获批准的国际联网通道存在法律风险；面向公众提供相关服务、经营相关业务的风险更高。

不同地区、不同时期的执法尺度不同，本文不构成法律意见，也不提供规避执法的建议。**在决定使用任何工具之前，请自行了解并遵守所在地的法律法规。**

技术层面的风险同样存在：

- **服务商看得到你的流量。** 除非使用端到端加密的应用，你把流量交给任何 VPN 服务商，它就处在能看到明文的位置。选服务商等于选一个你愿意信任的中间人。
- **免费服务可能更贵。** 见第十三节。
- **"匿名"通常只是营销词。** 大多数服务需要支付，支付记录就是身份关联点。真正匿名的方案，代价通常是可用性。
- **不要用同一套凭据。** 在任何第三方服务注册时，使用与主账号不同的邮箱和密码。
